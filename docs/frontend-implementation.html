Building the conversation UI — implementation plan

How the prototype becomes real code in src/: a transcript model over the existing event stream, a three-pane shell, and two small bridge additions — shipped as an incremental PR ladder.
Design: frontend.html · visual spec: frontend-mockup.html · interactive UX: frontend-prototype.html

The prototypes are a design spec, not the code — the implementation follows them but is rebuilt in the app's real stack (React + TS + Tailwind v4 + shadcn/ui). The guiding move: build the UI over the AgentEvent stream that already exists, so the biggest visual jump needs zero main-process changes; the two pieces that do need the bridge (Stop, inline consent) come later as isolated PRs. Every step ships on its own.

1. The load-bearing piece — a transcript model

Replace AgentProbe's "stringify each event into a capped array" with a pure reducer that folds the event stream into a structured tree. This is the one thing to get exactly right (tool pairing by toolUseId, turn grouping). 

type Origin = "host" | "vm";   // derived from tool name: Bash → vm, Read/Glob/Write → host

type Block =
  | { kind: "text"; text: string }
  | { kind: "tool"; id: string; name: string; origin: Origin;
      input: unknown; result?: unknown; status: "running" | "done" | "error" }
  | { kind: "consent"; requestId: string; path: string; state: "pending" | "allow" | "deny" };

type Item =
  | { role: "service"; text: string }
  | { role: "user"; text: string }
  | { role: "assistant"; time: string; blocks: Block[] };

type Conversation = {
  sessionId?: string; title: string;
  items: Item[]; grants: string[];
  status: "idle" | "running" | "done";
};

function applyEvent(c: Conversation, e: AgentEvent): Conversation

applyEvent mapping:

  • task_started → status: "running"
  • session_started → set sessionId (+ title from first user message)
  • assistant_message → append/merge a text block into the current assistant turn
  • tool_use → push a tool block keyed by toolUseId, status: "running", origin from the name
  • tool_result → find that block by toolUseId, attach result, set done/error (from isError)
  • task_finished → status: "done"

Because it's pure, a transcript.test.ts that feeds event sequences and asserts the resulting tree is the single highest-value test in the whole effort — it catches the pairing/grouping bugs before they reach the screen. Lives in a ConversationProvider with useReducer (the app has no store today; per KISS, don't add one until PR 5 needs it).

2. Component tree

AppShell three-pane grid (Sidebar | ConversationView | InfoPane*) ├─ Sidebar ConversationList · NewTask · (⌘K search) ├─ ConversationView │ ├─ Header │ ├─ Transcript items → UserMessage | ServiceMessage | AssistantTurn │ │ └─ AssistantTurn → blocks → MarkdownText | ToolCard | ConsentCard │ └─ Composer textarea (Enter / Shift+Enter) · Send / Stop └─ InfoPane* grants · session · model · VmStatusPill · tool counts (*collapsible)

Reuse what exists: ui/{button,dialog,input}, the Settings dialog, and VmStatusPill (folded into the InfoPane). New, custom-but-Tailwind'd: ToolCard, ConsentCard, the bubbles, and the service line.

3. Styling & rendering

  • Tailwind v4, not the prototype's hand-CSS. Port the prototype palette into index.css @theme as semantic tokens (host = blue, vm = violet, agent = amber); the prototype HTML is the visual reference, not the source.
    host = blue vm = violet agent = amber
  • Markdown: react-markdown + remark-gfm, with a code-block component (copy + light highlight). "Streaming" today means text arrives per event/block, not per token (that's how runTask relays) — append as it comes.
  • Auto-scroll + jump-to-latest; virtualize the transcript only once it gets long.

4. The two bridge additions

cancelAgentTask(taskId) — tiny

preload exposes it → ipcMain.handle("cancel-agent-task") → activeTasks.get(taskId)?.abort(). Main already holds the AbortController per task; it's just not reachable from the renderer. Wires the Stop button.

Inline consent — medium, security-sensitive

Today consent.ts shows a native dialog inside the MCP tool handler. To render the inline [Allow]/[Deny] instead, the request round-trips to the renderer:

  • new AgentEvent variant consent_request { requestId, path } — main emits it;
  • new bridge method respondConsent(requestId, allow) — resolves the pending promise inside requestDirectoryConsent;
  • keep the native dialog as a fallback (no window / headless) so the gate never hangs.

5. PR ladder

Each step is independently shippable; PRs 1–2 are pure renderer work.

1
Transcript model + read-only conversation view renderer
The reducer + types + Transcript/AssistantTurn/ToolCard/MarkdownText/ServiceMessage, swapped in for the raw-JSON <pre>. No main changes. Biggest visual jump. Ships with transcript.test.ts.
2
Three-pane shell + composer renderer
Sidebar (single conversation to start), InfoPane (grants / session / model / VM from existing getVmStatus·onVmStatus·getSettings), real composer. Fold in VmStatusPill.
3
Stop button bridge
Adds cancelAgentTask to preload/main. Small.
4
Inline consent bridge
The round-trip + ConsentCard replacing the native dialog. Touches the security path — re-verify the deny → request → retry loop end to end.
5
Conversation history + persistence renderer
Multiple conversations keyed by sessionId, --resume any, persisted (disk / localStorage). This is where a store (Zustand) earns its place.
6
Polish renderer
Code copy/highlight, jump-to-latest, virtualization, dark-mode toggle (#25), model picker. (Edit/Grep enablement — a separate follow-up — slots in wherever.)

6. Verification

  • Unit: transcript.test.ts — event sequences → expected tree. Pure, cheap, catches the pairing/grouping bugs.
  • End-to-end: drive the real app via CDP (as we did for the proxy and path-gating), with CAPYBARA_AUTO_CONSENT=1 for the allow path.

Notes & risks

  • PRs 1–2 are pure renderer work — low risk, high payoff; start there.
  • The consent round-trip (PR 4) is the one change touching the security path — keep the native-dialog fallback, and re-verify the gate.
  • KISS: single conversation + useReducer until PR 5; don't pull in a store or persistence early.
