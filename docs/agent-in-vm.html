Capybara · architecture · proposed

Agent-in-VM

Move the entire agent inside the Lima VM and shrink the Electron host to a control plane: it holds the API key, proxies LLM traffic, mounts approved directories, and bridges the UI — nothing else. The agent is born inside a kernel-enforced jail with nothing worth stealing. This mirrors what Anthropic's own desktop agent (Cowork) and OpenCowork ship: the brain runs in the VM, the host is the bridge.

Boundary

The VM is the trust boundary — enforced by the hypervisor, not by a config flag. Everything the model can influence lives inside it.

Secret

The agent never possesses the API key. The host injects it onto outbound LLM requests; a fully compromised agent has nothing to exfiltrate.

Egress

Deny-by-default. The VM reaches the network only through the host's domain-allowlisting proxy.

Host files

Reachable only via explicit VirtIO mounts, one directory at a time, each gated by a permission prompt.

The shape

Two boxes. The host (top) holds the key and is the only exit to the network; the VM (bottom) is the agent's home and the trust boundary. Everything inside the VM is treated as already compromised.

Enforced vs configured boundary

Today — agent on host

Containment is a request the untrusted runtime interprets about itself.

  • allowedTools — a flag, honored by the thing you don't trust
  • key in the agent's env — readable if the runtime is owned
  • full macOS filesystem — Bun has no sandbox
  • open network — can phone home directly
  • blast radius: the whole Mac + the key

Agent-in-VM

Containment is a wall the agent cannot reach — the hypervisor enforces it.

  • kernel boundary — VM, not a config flag
  • no key in the VM — host injects it on egress
  • only mounted dirs — explicit, per-directory
  • egress via host proxy — deny-by-default allowlist
  • blast radius: the VM, and nothing else

A turn, end to end

  1. UI sends the prompt uihost
    The webview hands the task to the Electron main process over IPC (contextBridge).
  2. Host dispatches into the VM hostagent
    The broker delivers start_task to the agent runtime inside the VM over the control channel. The agent owns the session (SDK session_id); resume continues prior turns.
  3. Agent reasons; needs the model agent
    The claude CLI issues an LLM request. The VM has no key and no direct internet, so the request is pointed at the host proxy (ANTHROPIC_BASE_URL → host).
  4. Host proxy injects the key and forwards host
    The egress proxy checks the domain against the allowlist, adds Authorization, and forwards to api.anthropic.com. The response streams back into the VM.
  5. Agent runs a command agentvm
    A tool/bash call goes to the supervisor in the same VM, which runs it under bwrap as the per-session user in /workspace — never leaving the jail.
  6. Agent needs a host directory agenthost
    It requests access; the host shows a permission prompt and, on approval, mounts that one directory over VirtIO at /sessions/<id>/mnt/<name>.
  7. Messages stream to the UI agenthostui
    Assistant text and the final result travel back over the control channel; the host bridges them to the webview. The turn ends; the agent process can exit cleanly.

Network egress — deny by default

Both halves matter: filesystem containment alone still lets a compromised agent phone home. Layered, so a single bypass isn't a breakout — the same posture Cowork ships.

LAYER 1

No raw sockets

  • the VM has no default route to the internet
  • direct outbound connections simply fail
  • the only reachable endpoint is the host
LAYER 2

Host proxy

  • all VM egress funnels through one host-side proxy
  • injects the API key the VM never holds
  • the single, auditable exit point
LAYER 3

Domain allowlist

  • only approved domains pass — e.g. the LLM API
  • everything else is blocked
  • new domains require an explicit prompt

What the move buys — and costs

Buys

  1. Enforced containment. Even total compromise of the model, the SDK, the claude binary, or any dependency is confined to the VM.
  2. Key is unstealable. The agent never holds it; the host injects it on egress. Nothing to leak.
  3. Tiny trusted root. The host shrinks to a key-injecting proxy + mounts + bridge — small enough to actually audit.
  4. Matches the desktop-agent peers. Cowork and OpenCowork converged on exactly this; the host's job (egress proxy, VirtIO mounts, bridge) is the validated shape.

Costs

  1. Linux agent runtime. Bun + the claude CLI must run in the VM (linux-x64), not on macOS — a second native build path.
  2. The host becomes an LLM proxy. A real forwarding service with its own failure modes, not just an stdio broker.
  3. Host files need mounts. "Work on my folder" becomes an explicit VirtIO mount + permission, not ambient host access.
  4. Trust shifts to the proxy. The proxy is now the trusted root — acceptable, because it's small and reviewable versus an opaque 200 MB binary.
Deliberate carve-outs, made visible. Some capabilities can't live in the VM — e.g. driving the user's real browser with their real cookies (Cowork runs this on the host on purpose). Treat each as a narrow, named hole the user understands, never a broad default the security argument silently leans on.
