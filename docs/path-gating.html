Path-gating — app-layer folder permissions for host file tools

Implementation plan. Bounds the host filesystem reach of the SDK built-in Read/Glob/Write/Edit/Grep tools with a deny → request → retry consent loop.
Implements architecture.html proposed-direction items 4–6 · full design in host-agent-vm-bash.html · follows PR #33 (c8a21d3)

Context

PR #33 made Read/Glob/Write run as SDK built-in tools natively on the host filesystem (and confined Bash to the VM). Those host file tools currently have no path restriction — they can touch any file the Electron process can (home dir, SSH keys, anything). That ungated host access is the deliberate, documented gap from the "host agent + VM bash" design: PR #33 shipped the capability without the boundary.

This plan adds the boundary. The agent may only access host paths the user has explicitly granted, enforced per tool call. It discovers the boundary by being denied, requests access through a consent tool, the user approves via a native dialog, and the agent retries. Grants are session-only and in-memory in the Electron main process; every new conversation starts empty and re-asks.

Why this shape

The in-process MCP server already runs in the Electron main process, and — critically — the TS SDK invokes hooks callbacks in that same process (they're JS functions called over the control channel, not shell hooks in the spawned claude binary). So the PreToolUse hook, the grant store, and the consent dialog all live in main with direct access to shared in-memory state — no new IPC and no renderer changes.

Verified against the SDK types: Options.hooks is Partial<Record<HookEvent, HookCallbackMatcher[]>>; the PreToolUse input carries session_id, tool_name, tool_input; deny is returned as { hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "deny", permissionDecisionReason } }; returning {} defers to the normal flow (which auto-approves allow-listed tools).

  1. claude → hook  Read(file_path) on an ungranted path; hook calls evaluateFileTool.
  2. hook → claude  grant store empty → deny + structured reason, surfaced as an is_error tool_result the model reads.
  3. claude → tool  model calls request_capybara_directory({ path }) → consent.ts shows a native dialog.
  4. user Allow → retry  grantDirectory(getSdkSessionId) records it; model retries Read; hook now returns {} → built-in runs.

Both the hook (input.session_id) and the grant-write (getSdkSessionId(), from runTask's sessionId) key on the SDK session id — the same value — so a grant made in step 3 is visible to the retry in step 4. resolveSession returns the VM id and must not be the grant key.

New files

new  electron/agent/grants.ts

Pure — the only module with real logic; the unit-test target.

export function grantDirectory(sessionId: string, dir: string): void;
export function evaluateFileTool(
  sessionId: string, toolName: string, toolInput: unknown,
): { allow: true } | { deny: true; reason: string };
  • const store = new Map<string, string[]>() — a set of granted dirs per session. One access level: a granted folder allows any file tool on paths inside it (read and write are not distinguished — KISS).
  • GATED: bare built-in name → pathField — Read→file_path, Write→file_path, Edit→file_path, Glob→path, Grep→path. Bare names (built-ins arrive unprefixed; the consent tool and Bash arrive as mcp__capybara__* and are absent from GATED).
  • normalize(p): expand leading ~ → os.homedir(); path.resolve() to collapse ..; falsy/relative → sentinel that forces a deny. Symlink/realpath resolution deferred (comment it as a known trust-boundary gap). grantDirectory normalizes too, so grants and candidates share one canonical space.
  • Match: candidate === dir || candidate.startsWith(dir + path.sep) (the + path.sep guard makes /foo/barbaz not match a grant of /foo/bar). Any granted dir covering the candidate path → allow, regardless of whether the tool reads or writes.
  • Early return: any toolName not in GATED → { allow: true }. This one line keeps the consent tool and mcp__capybara__Bash ungated.
  • Deny reason (structured; suggests the containing directory):
Path "/Users/x/Desktop/a.txt" is not connected. Call
request_capybara_directory({ path: "/Users/x/Desktop" })
to request access, then retry.

new  electron/consent.ts

Native dialog — the only side-effecting piece.

export async function requestDirectoryConsent(p: string): Promise<boolean>;
  • First line: if (process.env.CAPYBARA_AUTO_CONSENT === "1") return true; (headless e2e).
  • const win = BrowserWindow.getAllWindows()[0]; then dialog.showMessageBox(win, { message: `Capybara wants to access ${p}`, buttons: ["Deny", "Allow"], defaultId: 0, cancelId: 0 }); return response === 1. Use getAllWindows()[0] — one window, and mainWindow is block-scoped/not exported.

edit  electron/agent/runTask.ts

Add hooks to the Options bag (~line 188). The input carries session_id, so no closure threading for the hook: 

hooks: {
  PreToolUse: [
    { hooks: [ async (input) => {
        const i = input as { session_id: string; tool_name: string; tool_input: unknown };
        const r = evaluateFileTool(i.session_id, i.tool_name, i.tool_input);
        if ("allow" in r) return {};
        return { hookSpecificOutput: {
          hookEventName: "PreToolUse",
          permissionDecision: "deny",
          permissionDecisionReason: r.reason,
        } };
    } ] },
  ],
},

No matcher (default-all; GATED early-returns for non-file tools). The deny surfaces as an is_error tool_result, which the existing relay() (runTask.ts:117–125) already forwards — no new AgentEvent.

Update the call (line 176) to pass the SDK-session thunk: buildTools(supervisor, resolveSession, () => sessionId ?? "").

edit  electron/agent/tools.ts

Signature → buildTools(supervisor, resolveSession, getSdkSessionId: () => string), mirroring the existing positional resolveSession thunk (no options-bag). Import requestDirectoryConsent from ../consent and grantDirectory from ./grants directly. Add to the returned array: 

tool("request_capybara_directory",
  "Request access to a host folder. Call this after a file tool is denied, then retry.",
  { path: z.string() },
  async (args) => {
    const ok = await requestDirectoryConsent(args.path);
    if (!ok) return { content: [{ type: "text", text: `User denied access to ${args.path}.` }], isError: true };
    grantDirectory(getSdkSessionId(), args.path);
    return { content: [{ type: "text", text: `Granted access to ${args.path}. Retry your file operation.` }] };
  })

Grants key on getSdkSessionId() — the same value the hook reads as input.session_id — deliberately not resolveSession's VM id.

Scope note — Edit / Grep

The gate covers all five host file tools (Read/Glob/Write/Edit/Grep) regardless of the allow-list, so it also pre-closes the reachable-but-unlisted Edit/Grep hole. Actually enabling them (adding to ALLOWED_TOOLS) stays a separate follow-up — now safe to flip because the gate already covers them.

Verification

  1. Unit (grants.test.ts), bun test electron: ungranted-path deny carrying the exact reason substring; allow after grantDirectory (for both a read tool and a write tool — one grant covers both); subpath allow; prefix-spoof deny (/foo/barbaz not under /foo/bar); ~ expansion; relative/missing-path deny; Glob with no path deny; per-session isolation (grant in A invisible to B).
  2. allowedTools.test.ts: consent tool present in ALLOWED_TOOLS.
  3. Static gates (check:electron): tsc --noEmit -p electron, oxlint -D correctness electron, oxfmt --check.
  4. End-to-end on the real app (drive via CDP, as in the PR #33 test):
    • Deny → request (no dialog needed): ask the agent to read a path under ~/Desktop. In the agent-event stream observe a tool_result with isError: true carrying the deny reason, immediately followed by a tool_use for request_capybara_directory. Proves gate + model reaction with zero dialog.
    • Allow path: relaunch with CAPYBARA_AUTO_CONSENT=1, same prompt; observe the retried Read returns isError: false. (Optionally one manual click-through of the real dialog without the env var.)

Deferred (out of scope, per docs + KISS)

  • VM-mount of granted dirs (so VM Bash sees them via the supervisor's connect_directory). Granted host dirs stay invisible to Bash — consistent with the system prompt's host/VM split. Follow-up.
  • Symlink / path-escape resolution (realpath). Documented trust-boundary gap.
  • Grant eviction / LRU. Bounded by process lifetime; no consumer needs it.
  • srt-style OS sandbox around the host agent. Deferred in the docs.

KISS guardrails (do NOT)

  • Don't pass requestDirectoryConsent as a buildTools param — single call site, import it.
  • Don't build an options-bag for buildTools; one getSdkSessionId thunk mirrors the existing resolveSession thunk.
  • Don't add a matcher to the hook; default-all + GATED early-return is simpler.
  • Don't add a new AgentEvent type for denials; the existing tool_result/isError path carries it.
  • Don't key grants off resolveSession (VM id) — use the SDK session id on both sides.
